# User delivery requirements

- The user wants the HTML application to remain easy to update. Do not build EXE artifacts unless explicitly requested again.
- For each user-facing app update, run `npm run package:html` and prepare the resulting versioned ZIP. Include the standalone HTML, Korean usage instructions, and editable project sources. Do not include node_modules, caches, desktop binaries, or browser profiles.
- The user explicitly requests downloadable ZIP delivery every time. Use an actual attachment/export capability when available. A file existing under /workspace does not establish download access. Never describe an internal path as a working download link unless delivery has been confirmed. If attachment is unavailable, state that ZIP creation succeeded but downloadable delivery remains blocked.
- File cards are intended as shortcuts to the user's original PC files. Clearly explain that pure HTML cannot reliably launch Windows default applications; do not silently describe browser previews as native original-file opening.
- The HTML ZIP now includes a Windows PowerShell loopback helper launched by `코션 실행.vbs` through a native WebView2 HTML host. No Node.js is required; use the installed Microsoft Edge WebView2 Runtime and redistribute the official SDK DLLs with license/provenance. File cards in helper mode must use original approved paths and ShellExecute, never download a copy. Browser-only mode remains a preview fallback and must be labeled clearly.
- For Explorer drag-and-drop, never guess an absolute path from a filename alone. In the v0.6 native window, obtain actual File paths via WebView2 AdditionalObjects/CoreWebView2File.Path. Do not show an extra original-file picker after a drop. In a general browser, explain that the native window is needed; retain explicit path paste.
- ZIP delivery through the user's GitHub repository has been authorized for app updates; publish the tested ZIP and provide its actual GitHub download link.
- v0.5 removes folder setup from the UI. Default Windows selection and Office conversion run in isolated STA worker processes so they cannot block the HTTP helper. Keep direct file-path paste as a visible fallback because native dialogs were unreliable on the user's PC.
- Preview provenance must be explicit: real PDF first-page rendering, embedded HWP/HWPX or Office thumbnails, Office read-only page export, or Windows thumbnail providers. On unsupported images, show the failure and fall back to text/data; never present file icons as first-page images. Do not claim Windows COM execution was validated on Linux.

- v0.6 uses a hidden VBS launcher and WinForms WebView2 host. Close the owned helper with the app; never hide an unmanaged server with no lifecycle. Keep Microsoft SDK DLL license and provenance in the ZIP. Existing Chrome/Edge IndexedDB is separate: preserve backup/restore migration instructions. Never claim Windows WebView2 execution was tested on Linux.

- v0.7 changes drawer deletion to cascade through contained board objects. Never delete the user’s original PC files. Keep in-session deletion undo, multi-selection/group geometry, drag-to-drawer identity, and persisted whole-object typography covered by tests. Context controls belong in one horizontal row below the insertion toolbar.

- v0.8 renames the product to 코션 (Cotion), with 코션 실행.vbs and a custom ICO/AppUserModelID. Preserve the legacy MoaWeb directory, moa-workspace IndexedDB and backup format. Rotation must not alter x/y/w/h. Keep multiline heading layout, actual text alignment, native-vs-object clipboard behavior and general undo/redo covered by regression tests. Do not reintroduce the format-reset button.

- v0.8.1 removes obsolete Moa launch aliases, CMD launchers and duplicate HTML. Ship one root `코션 실행.vbs` and one `코션.html`. Preserve needed PowerShell/SDK/license files and editable sources; do not reintroduce duplicate launchers. Extract updated ZIPs into a fresh folder; never delete user data during cleanup. Internal MoaWeb/storage/protocol names remain compatible.

- v0.9 moves placement and all following object controls to an object context menu (right click, Shift+F10 or the toolbar menu button); text/appearance/type controls remain in the horizontal toolbar. Insertion extras are expanded. Table insertion must show row/column/size/header settings with bounded cell count. Standalone checkbox insertion is removed: migrate old checkboxes to text paragraphs, preserve IDs/parents/completion, and support per-paragraph checks in text, notes, shapes and table cells with caret, composition, split/merge, clipboard, history and backup regression coverage.

- v0.10 removes object alignment and the toolbar object-menu button. Use right-click/Shift+F10. A unified Link dialog supports internet/page cards and hyperlinks on arbitrary objects, validated http(s)/page IDs, F2 edit/Esc finish, Ctrl+K, and context copy/cut/session object paste. Legacy web/pagelink cards remain readable. Calendar typography must respond to live object size and dates stay top-left; drawer wheel scroll must target its list without scrolling the board. New shapes start regular with aspect lock; preserve existing dimensions. Path paste is an advanced fallback inside File Connect, not a toolbar action.
