# User delivery requirements

- The user wants the HTML application to remain easy to update. Do not build EXE artifacts unless explicitly requested again.
- For each user-facing app update, run `npm run package:html` and prepare the resulting versioned ZIP. Include the standalone HTML, Korean usage instructions, and editable project sources. Do not include node_modules, caches, desktop binaries, or browser profiles.
- The user explicitly requests downloadable ZIP delivery every time. Use an actual attachment/export capability when available. A file existing under /workspace does not establish download access. Never describe an internal path as a working download link unless delivery has been confirmed. If attachment is unavailable, state that ZIP creation succeeded but downloadable delivery remains blocked.
- File cards are intended as shortcuts to the user's original PC files. Clearly explain that pure HTML cannot reliably launch Windows default applications; do not silently describe browser previews as native original-file opening.
- The HTML ZIP now includes a Windows PowerShell loopback helper launched by `모아 실행.cmd`. Keep it dependency-free for Windows users. File cards in helper mode must use original approved paths and ShellExecute, never download a copy. Browser-only mode remains a preview fallback and must be labeled clearly.
- For Explorer drag-and-drop, never guess an absolute path from a filename alone. Resolve name, size and modification time within explicitly selected folders; reject zero or ambiguous matches and offer native file selection.
- ZIP delivery through the user's GitHub repository has been authorized for app updates; publish the tested ZIP and provide its actual GitHub download link.
- v0.5 removes folder setup from the UI. Default Windows selection and Office conversion run in isolated STA worker processes so they cannot block the HTTP helper. Keep direct file-path paste as a visible fallback because native dialogs were unreliable on the user's PC.
- Preview provenance must be explicit: real PDF first-page rendering, embedded HWP/HWPX or Office thumbnails, Office read-only page export, or Windows thumbnail providers. On unsupported images, show the failure and fall back to text/data; never present file icons as first-page images. Do not claim Windows COM execution was validated on Linux.
